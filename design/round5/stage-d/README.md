# Round 5 方案 D：自然高度舞台＋緊湊操作區

預覽：`index.html?stage=d`（A／B／C 的比較資料在 `../stage/`，切換參數照舊：`?stage=a|b|c|d`，記在這個分頁）。

## 做法（只改版面，`src/dialog.css` 的 `:root[data-stage="d"]` 規則）

1. **舞台不再撐滿畫面：** `.stage-wrap` 由 `flex: 1 0 auto` 改成 `flex: none`，高度是 SVG 加上一段固定比例的地板：`min-height: 場景高度 × 1.25`（直向；橫向拿著手機時不加，保留每一點高度）。所有階段同一個高度，所以從報到進入坐禪時舞台不會變高或變矮。
2. **操作區緊接舞台：** 計時卡不再用 `margin-top: auto` 推到手機底部；合掌請打那一列去掉原本的 `margin-block: -4px`，舞台、合掌請打、計時卡之間都是頁面原有的 14 px 間距。頁面在內容結束處結束，比畫面長時自然捲動。沒有用負 margin、絕對定位或依手機高度寫死的位移。
3. **結算卡不會被裁切：** 結算卡原本 `position: absolute; inset: 0` 蓋在舞台上，需要舞台夠高。D 讓它和 SVG 放在同一個 grid 格子裡（`grid-area: 1 / 1`），舞台的高度自然是兩者中較高的那一個：卡片多長都放得下，也不用為結算預留高度。

不變的：SVG viewBox、所有物件與角色座標、住持造型、巡堂路點、香板動畫、計時與分心規則、深淺色與多語系。

## 仍需注意

- D 不填滿手機：坐禪時計時卡下方會留一段頁面底色，360 寬約 120 px、390 寬約 150 px、412 寬約 195 px（在頁面最下面，不在舞台和按鈕之間）。這是「不刻意填滿」的代價；畫面越高的手機越明顯。
- 報到時，412 寬的舞台比 A 略矮（350 → 319 px），因為 A 在那裡也會撐滿；320 寬則略高（191 → 238 px），報到時多一點捲動。
- 底部安全區域：頁面本來就在 `body` 加了 `env(safe-area-inset-bottom)` 的內距，D 沒有改它；無頭瀏覽器無法模擬瀏海與手勢列，需在實機確認。
- 系統字體放大只用「網頁字體 130%」模擬；實機的系統字體設定可能放大得更多。
