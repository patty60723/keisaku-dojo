# 技術文件

這份文件只寫技術細節與演算法:程式怎麼組起來、各個偵測和計算怎麼做、資料怎麼存。
產品行為(對話流程、坐禪帳的規則)寫在 [`onboarding-spec.md`](onboarding-spec.md) 和 [`journal-spec.md`](journal-spec.md)。

## 1. 架構與建置

- 純前端、沒有框架、沒有外部 JS 套件。只從 Google Fonts 載入三套字型(霞鶩文楷 TC、補日文假名的 Klee One、數字用的 Fredoka),載不到時退回系統字型。
- 上線的是單一個自帶 CSS / SVG / JS 的 `index.html`,由 `build.py` 從 `src/` 組出來:

  | 檔案 | 內容 |
  |---|---|
  | `src/style.css` | 色彩 token(淺色 / 深色)、版面、禪堂 SVG 的上色 class、計時卡片 |
  | `src/extra.css` | 炷香指示、偵測狀態 |
  | `src/dialog.css` | 對話框、彈出面板(手卷)、坐禪帳、統計、導覽等;後面的規則會覆寫前面的 |
  | `src/body.html` | 頁面結構;`{{SVG}}` 由 `svg.html` 取代 |
  | `src/svg.html` | 禪堂場景(viewBox `0 0 400 280`) |
  | `src/i18n.js` | 日文、英文字典 `I18N`(key 是中文原文) |
  | `src/app.js` | 全部程式,包在一個 IIFE 裡 |

- `build.py` 會從 `sw.js` 讀出快取版本 `VERSION`,填進設定最下面顯示的版本號,所以版本只要在 `sw.js` 改一個地方。
- `python3 build.py` 產生 `index.html`;`python3 build.py preview` 產生 `preview.html`(左上角多一個「預覽版」標籤,其餘相同)。`python3 build.py debug` 產生 `debug.html`:注入 `window.KEISAKU_DEBUG = true` 和建置時間,所有儲存的 key 前面加 `debug:`(不會動到正式版的紀錄和設定),收藏全部解鎖、導覽視為看過,畫面下方的浮動面板可以切季節、日夜、打一下、坐站、開收藏冊。
- `python3 build_lab.py` 從 `app.js` 裡 `/*SND-START*/ … /*SND-END*/` 之間的聲音引擎產生 `soundlab.html`,所以試聽台跟 App 永遠用同一份聲音程式。
- `<head>` 裡有一小段同步 script,在第一次繪製前把存好的深淺色套到 `<html data-theme>`,避免閃一下另一個主題。

## 2. PWA 與快取

- `manifest.webmanifest` 的 `id` 寫完整路徑 `/keisaku-dojo/`。寫 `./` 會被解析成網域根目錄,跟同一個 `github.io` 網域上的其他 App 撞 ID。
- `sw.js` 的快取策略:

  | 請求 | 策略 |
  |---|---|
  | 頁面導覽(`mode: navigate`) | 網路優先。成功就以**各自的 URL** 存進快取;離線時先找同一個 URL(忽略 query),再退回 `./index.html` |
  | Google Fonts | 快取優先,存進獨立的 `keisaku-fonts`,不隨版本清除 |
  | 同源的其他檔案(圖示、manifest) | 快取優先 |

  頁面要用各自的 URL 快取,是因為以前全部存成 `index.html`,打開 `soundlab.html` 或 `preview.html` 會蓋掉 App 本體。
- 圖示檔名帶版本號(`icon-192-v2.png`…)。換圖示時一定要換檔名:Android 的 Chrome 只會偶爾(約一天一次、從主畫面開啟時)重新檢查 manifest,網址不變很容易被判斷成沒變;Service Worker 對圖示也是快取優先。
- 每次上版把 `VERSION` 加一:`activate` 時會刪掉所有 `keisaku-shell-*` 舊快取,並用 `skipWaiting` + `clients.claim` 讓新版立刻接手。
- `notificationclick` 會把已開著的 App 視窗拉到前面,沒有的話開一個新的。

## 3. 時間與狀態機

### 坐禪的階段

```
idle(報到對話)→ settle(放手機的 3 秒)→ focus → break → ready(對話)→ settle → focus …
                                          ↘ leave(暫離)→ settle → focus
最後一炷 focus 結束 → 結算卡 → idle
```

- 所有計時都存「結束的時間點」(`P.end = Date.now() + 長度`),每 250 ms 的 `tick()` 用 `P.end - Date.now()` 算剩下多少。
  頁面被瀏覽器暫停後再回來,時間還是對的,不會因為計時器被節流而變慢。
- 暫離時把剩餘毫秒存進 `P.left`,回座並重新放好手機後 `P.end = Date.now() + P.left`。
- 坐禪中用 Screen Wake Lock 讓螢幕保持亮著;切回頁面時會重新申請。

### 住持的動作

- 住持一次只做一件事。打人、拿香板、放回香板這類動作都排進佇列(`enqueue` → `pump`),依序 `await` 執行。
- 佇列空了,就由 `settleMonk()` 依階段決定閒置模式:`patrol`(巡堂)、`host`(站在旁邊對話)、`rest`(去茶几喝茶)。
- 位置在每一幀(`requestAnimationFrame`)朝目標移動,`dt` 上限 50 ms,避免切回頁面時瞬移。走路時身體有上下擺動。開啟系統的「減少動態效果」時,走路不擺動,麻糬跳上蒲團、對話打字、面板的展開收起都直接完成,煙和呼吸的循環動畫也停掉。

## 4. 拿起手機的偵測(平衡儀)

輸入是 `devicemotion` 的 `accelerationIncludingGravity`。iOS 要先 `DeviceMotionEvent.requestPermission()`,而且必須在點擊事件裡同步呼叫,所以放在「準備好了」和「回座」按鈕的處理函式裡。

每一筆讀數 `v = (x, y, z)`:

1. **晃動量** `jerk = |v − lp|`,`lp` 是上一刻的低通結果。
2. **低通濾波(重力方向)** `lp = 0.85·lp + 0.15·v`。
3. **靜止時間**:`jerk > 1.2` 就歸零,否則累加 `dt`(單筆最多算 0.1 秒)。
4. 坐禪開始時,把當下的 `lp` 存成基準 `base`。之後看 `ang = angle(lp, base)`。

判斷:

| 狀態 | 條件 |
|---|---|
| 被干擾的這一刻 | `ang > 20°` 或 `jerk > 3.5` |
| 算拿起來 | 干擾分數 `score` 超過 0.6 秒。干擾時 `score += dt`,沒干擾時 `score −= 0.5·dt`(不低於 0),所以短暫碰到不會算 |
| 算放回去 | 靜止超過 1.5 秒且 `ang < 15°`,或靜止超過 3 秒且手機是平躺的(換一面放也算) |
| 拿著不放 | 每 20 秒再打一下 |

- **落座時:** 倒數 3 秒後,還要連續靜止 0.8 秒才記基準。
- **讀不到感應器時:** 沒拒絕權限,卻從來沒收到 `devicemotion`,就退回只偵測「離開畫面」,計時卡片會顯示「⚠ 只能偵測切出畫面」。
- **放回去之後:** 每次放回去都用新的位置當基準,所以換個角度放也可以。

## 5. 離開畫面的偵測

- 坐禪中 `visibilitychange` 變成 hidden 時記下時間。
- 回來時計算 `away = min(now, P.end) − hiddenAt`:
  - 小於 2 秒:不算
  - 2 秒以上:打一下
  - 90 秒以上:再補一下
- 休息時不偵測。

## 6. 休息結束與通知

- 休息到時間時,`endBreak()` 會看頁面是不是在背景:
  - **在背景:** 標記 `awaitReturn`,用 `ServiceWorkerRegistration.showNotification` 發通知(tag `keisaku-break`、`renotify`),等使用者回來才開始對話。
  - **在前景:** 直接開始對話。
- 回來時算超時 `late = now − 休息結束時間`,滿 1 分鐘就記成 `lateMin`,存進下一炷的紀錄。
- **限制:** 沒有推播伺服器,通知只能在頁面的 JS 還在跑時發出。Android 會節流或凍結背景頁面,所以通知可能晚到或沒有;要準時,得加 Web Push 伺服器排程。

## 7. 聲音(Web Audio,全部即時合成)

- `AudioContext` 在第一次點擊時建立(瀏覽器的自動播放限制)。
- **鐘:** 523 Hz 的正弦波疊上 ×2.42、×4.05、×0.5 的泛音,各自有不同的衰減時間,做出寺鐘的不和諧泛音。止靜三鐘每聲間隔 1.5 秒。
- **噪音底:** 預先產生約 4 秒的白 / 粉紅(Paul Kellet 濾波)/ 棕噪音 buffer,接縫交叉淡化避免喀聲;每一層從隨機位置開始循環,疊在一起時才不會對齊。
- **空間:** 每個聲音事件都經過一個立體聲定位,並分成乾聲和送進殘響兩路。殘響是 `ConvolverNode`,脈衝響應即時產生:3.4 秒的立體聲雜訊,振幅乘上 `(1 − t)^2.8` 衰減(`hallReverb`)。
- **共用工具:**
  - `shape()`:在參數上排一串短的線性斜坡,畫出不規則的包絡線,隨時取消也不會爆音。
  - `wander()`:平滑的隨機漫步。
  - `burst()`:一小段濾波雜訊。
  - `blip()`:一個滑音。
- **背景聲音都是「稀疏事件」,不是連續的雜訊:**
  - **雨:** 每滴是一個很短的共振喀聲(窄頻帶的雜訊在響),不是滑音,滑音聽起來像鳥叫。
    - 音量大多很小(`random³ × 0.4`),5% 機率出現大顆的雨滴。
    - 間隔在 `dropGapMin`–`dropGapMax` 之間;整體雨勢每 4–10 秒在 0.25–1 之間緩慢漂移。
  - **海浪:** 每一波先湧上 2.5–6 秒,湧越久能量越大:落地的碎浪越響(粉紅 + 白 + 棕三層)、泡沫越多、退潮越長(`waveBackMin`–`waveBackMax`)。底下還有一層會自己漂移的遠方浪聲。
  - **森林:**
    - 幾隻鳥:7 種叫法,各自成段地唱
    - 蟋蟀:一聲是 3–4 個高頻脈衝
    - 樹葉:一陣風吹過,帶通雜訊的中心頻率隨風勢起落、從一邊移到另一邊,上面疊著葉子的細碎抖動
    - 一隻青蛙:脈衝串的呱聲,每次從左或右傳來
  - **風鈴:** 6 根音管,D6 E6 F♯6 A6 B6 D7(五聲音階,可以再升 0–2 個八度)。
    - 平常多半只撞一下,偶爾隔一會兒再一下。
    - 起風時,風越大撞越多次、越響(`gustKnocksMin`–`gustKnocksMax`)。
    - 每一下是 2–3 根不同的管子幾乎同時響,不會跟上一下是同一根。
- **和音:** D 大調五聲音階的 5 個開放和弦,每個和弦 9–12 秒,70% 機率換到清單裡的下一個,其餘隨機。每個音依序間隔 0.35 秒進來,2.6 秒淡入、長長淡出;偶爾在上面輕輕點一兩個高音。
- **淡入淡出:** 背景聲音在止靜三鐘敲完後才淡入(約 3.8 秒後),開靜、暫離、結束時淡出,休息時不播。
- 可調參數都集中在 `SND` 物件,`soundlab.html` 的滑桿直接改它。

## 8. 畫面座標

- 禪堂是一張 viewBox `400 × 280` 的 SVG,寬度撐滿,高度隨寬度等比縮放。
- 疊在禪堂上的 HTML(對話泡泡、「啪!」、星星、木牌、掛軸、方窗和坐禪帳的點擊範圍)都用「SVG 單位」定位:`.app` 設成 `container-type: inline-size`,一個 SVG 單位 `--u = (100cqw − 3px) / 400`(3px 是外框),例如 `top: calc(var(--u) * 146)`。
  - 不能用禪堂高度的百分比:禪堂容器會長高去填滿畫面,百分比會跟著變。
- **延伸的地板:** 禪堂容器長高時,下面露出的部分用 CSS 背景畫成榻榻米。織紋是 `repeating-linear-gradient`,週期跟 SVG 裡的 `pattern` 一樣是 3 個 SVG 單位,而且都從 y = 0 開始,所以接縫處紋路連續;直線的疊蓆邊放在 68%(x = 272 / 400)。
- **左右對稱:** 以掛軸(x = 200)為中軸。圓窗中心 (86, 98)、半徑 33;方窗是它的鏡像,中心 (314, 98)、邊長 64。堂規木牌中心 x = 38,坐禪帳中心 x = 362。左牆的空位放香案(`#incenseTable`,中心 x = 146),右邊對應的是方窗下的行燈;香板靠在右柱(`RACK_X = 375`)。住持喝茶時站在香案右邊(`TEA_X = 190`)面向左。
- **窗景:** 兩扇窗看的是同一個季節。`renderScene()` 把同一段 SVG 寫進圓窗的 `#winView` 和方窗的 `#sqView`;方窗那份左右翻轉(`scale(-1 1)`),看起來像從另一個角度看同一棵樹。各自用 `clipPath` 裁成圓形和方形。
- **線香計時:** 香長 `44 × 剩餘比例`。火點和煙的位置跟著香頂移動;煙的外層 `<g>` 負責往下移,內層 path 負責飄動,因為 CSS 動畫的 `transform` 會蓋掉 SVG 的 `transform` 屬性。
- **夜裡的光(深色模式):**
  - **開關:** 色彩 token `--night-o` 在淺色是 0、深色是 1,所有只在夜裡出現的元素都掛 `.night { opacity: var(--night-o) }`。這跟月亮的 `--moon-o` 是同一招,切換主題時不用跑 JS。
  - **行燈:** 木框和米白紙罩白天晚上都在;晚上多疊一層發光的紙(`#andonPaperLit`),加上光暈(`#andonLight`,一個半徑 135 的 `radialGradient`,中心不透明度 0.32,分五段慢慢衰減到 0)和一圈模糊過的地面光。行燈放在方窗下的榻榻米上。
  - **月光:** 兩扇窗前的榻榻米上各有一片淡藍的光,整組用 `mix-blend-mode: screen` 疊上去(一般的半透明疊色會把橄欖色地板混成灰色,`screen` 只會提亮)。圓窗那片是 `radialGradient` 填的橢圓,方窗那片是梯形,都經過 `stdDeviation 8` 的高斯模糊,所以邊緣很軟。同一個月亮照進來,所以兩片都落在各自窗戶右邊 30 個單位,窗格影子(`clipPath` 裁出的淡線)也往同一個方向展開。
  - **窗外的動態:** 春天花瓣、秋天紅葉、冬天雪花是 `.drift` 元素,用 CSS 動畫往下飄並左右擺動,每片的週期和起始時間錯開;夏天的螢火蟲在 `.night` 裡,只有晚上出現,用不透明度閃爍。開啟「減少動態效果」時飄落的東西整個隱藏,螢火蟲停止閃爍。
  - **搖曳:** `#andonLight` 的不透明度用不規則的 keyframes 在 0.84–1 之間變化。香板打下去時(`impact()`)換成一段 0.8 秒的 `jolt` 動畫,`animationend` 時拿掉 class,回到搖曳。開啟「減少動態效果」時兩者都停掉。
  - **休息時變暗:** `setStatus()` 把目前階段寫到 `#stageWrap[data-phase]`。休息時光暈降到 0.6、發光紙降到 0.75 倍,有 2 秒的過渡。

## 9. 資料儲存

全部存在 `localStorage`,不上傳任何地方。第一次存紀錄時會呼叫 `navigator.storage.persist()`,降低被瀏覽器清掉的機會。

| key | 內容 |
|---|---|
| `keisaku-log-v2` | 坐禪紀錄陣列,一炷一筆(見下) |
| `keisaku-last-v1` | 上次的設定 `{ task, focusMin, rounds, breakMin }` |
| `keisaku-presets-v1` | 常用設定,最多 3 組 |
| `keisaku-opts-v1` | `{ motion, sound, notify, goal, theme, ambient, ambVol, music }` |
| `keisaku-rules-asked-v1`、`keisaku-tour-v1`、`keisaku-leave-told-v1` | 開場說明、導覽、暫離說明是否已經講過 |
| `keisaku-tip-journal-v1`、`keisaku-tip-leave-v1`、`keisaku-tip-collect-v1` | 「去坐禪帳看看」「可以暫離」「禪堂多了收藏冊」三個一次性提示是否出現過 |
| `keisaku-collect-v1` | 收藏冊:`{ scroll, wear: { head, body, extra }, seen }`,目前掛的掛軸、三格各戴的配件、已經通知過的收藏(見第 13 節)。v17 以前的 `acc` 會依配件的格子搬進 `wear` |
| `keisaku-notify-asked`、`keisaku-persist-asked` | 是否問過通知權限、是否申請過持久儲存 |

紀錄一筆:

```js
{ t: 1791275279901,      // 存檔時間(ms),跟 d 一起當唯一鍵
  d: '2026-10-06',       // 當地日期
  task: '讀書', min: 25, hits: 0,
  full: true,            // 有沒有坐滿這一炷(只有坐滿的才蓋章、算連續天數)
  leave: 1,              // 有暫離才有
  late: 4,               // 這炷前的休息超時幾分鐘,有才有
  goal: 4 }              // 存檔當時的每日目標,有設才有
```

- **沒存的情況:** 分鐘數為 0 而且沒被打的一炷不存。
- **備份格式:** `{ app: 'keisaku-dojo', version: 2, exported, log, presets, collect }`。`collect` 只有 `{ scroll, wear }`(v17 以前的備份是 `acc`,一樣收);匯入時只在手機上還是預設(「靜」、不戴)時才套用,而且只收清單裡有的名稱。
  - 匯入時用 `validEntry` 只收合理的紀錄:`t` 是數字、`d` 是 `YYYY-MM-DD`、`min` 是 0–240 的整數、`hits` 是 0–999 的整數、`task` 是文字(或沒有)、`full` 是是非值(或沒有)。收進來時由 `cleanEntry` 整理,事項名稱截到 12 字,並保留合理的 `leave`、`late`、`goal`。
  - 常用設定(備份裡的、或手機裡存的上次設定和常用設定)一律經過 `validCfg`:事項名稱 1–12 字、每炷 5–120 分、1–8 炷、休息 0–30 分,不合理的就不用。例如寫著「10 億炷」的常用設定,如果沒擋,畫炷香圖示時會讓 App 卡死。
  - 畫面上用到 `innerHTML` 的地方,事項名稱都先經過 `escapeHtml(String(…))`,就算儲存裡有格式錯的資料,也不會當掉或被插入 HTML。
  - 以 `t|d` 判斷是不是已經有了,只加入新的,不會覆蓋或刪除。

## 10. 坐禪帳的計算

- **每天彙總**(`dayMap`):把紀錄依日期合併成 `{ min, hits, full(坐滿炷數), goal(當天最大的目標), tasks }`。
- **印章**(`stampKind`):

  | 條件 | 印章 |
  |---|---|
  | 沒有坐滿任何一炷 | 小紅點(有分鐘數或被打過才蓋) |
  | 坐滿且一下都沒被打 | 不動 |
  | 坐滿,當天 ≥ 75 分 | 合掌 |
  | 坐滿,當天 25–74 分 | 坐 |
  | 坐滿,當天 < 25 分 | 淡淡的坐 |

  每個印章的旋轉角度(±7°)和偏移量(±4)由日期字串的 FNV-1a 雜湊算出來,同一天每次畫都一樣,不同天看起來像手蓋的。
- **連續天數**(`streakInfo`):從今天往回數,每天至少坐滿一炷就算。今天還沒坐不會中斷,從昨天開始數。
- **每日目標達成:** 當天坐滿炷數 ≥ 當天的目標。
- **統計期間:**
  - 七日、三十日:以今天為最後一天,每天一格。
  - 全部:從第一筆紀錄的月份開始每月一格,最多 12 個月。
- **格線值**(`gridValue`):從 5、10、15、20、30、45、60、90、120……分裡,選不超過最大值的最大那一個。圖的頂端是最大值 × 1.15,留空間給籤紙。
- **籤紙定位:** 中心對準那根香,但限制在圖的寬度內;尖角另外限制在籤紙兩端各留 10 px,不會跑到紙外面。
- **住持評語:**
  - 跟「前一段同樣長度的期間」比坐禪分鐘數:多 ≥ 30 分算進步,少 ≥ 30 分用安慰的語氣,其他算差不多。
  - 被打:看每炷平均。比前一段少 0.1 以上說有進步,大於 1.2 提醒把手機放遠(安慰句之後不加這句)。
  - 這段期間之前沒有任何紀錄時不比較。
  - 時間的口語說法(`talkMin`):60 分以下說「N 分鐘」,以上四捨五入到半小時,例如「1 小時半」。

## 11. 分享圖

- 1080 × 1350 的 canvas。
- **禪堂畫面:** 把 SVG 複製一份,逐一把每個元素算好的 `fill`、`stroke`、`opacity`、`display`、字型、`mix-blend-mode` 等寫進 `style`,因為原本的顏色來自 CSS class 和變數,單獨的 SVG 圖片讀不到。接著序列化成 `image/svg+xml` 的 Blob,載入成圖片再畫上 canvas。
- **字型:** 文字用 `document.fonts.load()` 確定字型載好再畫。
- **提前產生:** 結算卡一出現就先產生 PNG,按「分享」時才不會因為等待而失去使用者手勢。
- **分享方式:** 支援 `navigator.canShare({ files })` 就叫出系統分享選單,否則用 `<a download>` 存檔。

## 12. 新手導覽

- 導覽時整個畫面蓋一層透明的擋板(`position: fixed; inset: 0`)。
- **視覺上:** 亮框是一個 `box-shadow: 0 0 0 200vmax` 的元素,外面一圈都變暗,中間透明。
- **點擊判定:** 擋板收到點擊時,比對座標是否落在亮框的矩形內:
  - 在框內:前進。步驟有 `sheet` 的話,先真的打開那個面板,等它的 `close` 事件才繼續;有 `act` 的話,直接執行那顆按鈕原本的動作。
  - 在框外:亮框抖一下,不前進。
- **說明框位置:** 目標在畫面下半部時,說明框改放到上方,不會蓋住要點的東西。
- **無障礙:** 說明框裡有一顆視覺上隱藏的「下一步」,每一步都把焦點移到它身上,鍵盤和螢幕報讀的使用者按 Enter 也能前進。

## 13. 收藏冊

- **不另存進度:** 拿到了什麼完全由坐禪紀錄算出來(`collectStats(log)` → 每項的 `need(stats)` 回傳 `[已有, 需要, 單位]`)。所以匯入備份,收藏就跟著回來;舊使用者更新後,以前坐的也直接算數。
- **統計項目:** 坐滿的炷數、沒被打的炷數、用過暫離仍坐滿的炷數、45 分以上坐滿的炷數、總分鐘數、單日最多坐滿幾炷、「準時回座的日子」(那天坐滿 2 炷以上而且沒有休息超時)、歷來最長的連續天數,以及每個季節各坐滿幾炷。
- **季節:** 依當地月份,2–4 月春、5–7 月夏、8–10 月秋、11–1 月冬(`seasonOf(t)`)。季節限定的收藏按每一炷的存檔時間歸季,跨年累計。
- **「新」的判定:** `seen` 記著已經通知過的項目。第一次載入時把當下已達成的全部標成看過,所以不會一次跳出一堆。之後每坐滿一炷,`collectAfterRound` 比對出新達成的,放進 `P.newItems`;結算卡上寫一行,按「好」之後住持各問一次要不要掛上第一幅新掛軸、戴上第一件新配件。匯入備份時,補進來的紀錄達成的項目也直接標成看過。
- **坐禪中不能換:** 收藏冊在 `settle`、`focus`、`leave` 階段只能看,按鈕標成 `aria-disabled`。
- **保底:** 存著的掛軸或配件如果不在清單裡、或條件已經不成立(例如紀錄被清掉),畫面上退回「靜」和不戴。
- **配件三格:** 每件配件有 `slot`(`head` / `body` / `extra`),每格同時只戴一件,點已經戴著的會拿下來(`equip`)。畫的圖層:身體類在 `#mochiAccBack`(手臂後面),頭和臉上、手上的配飾在 `#mochiAcc`,放在蒲團旁的配飾(`place: 'side'`,小貓、團扇、木魚、提燈、茶碗)在 `#accSide`;膝上毯站起來時改畫成摺好放在蒲團上(`#accCushion`)。
- **被打時的反應:** `impact()` 對每件戴著的配件呼叫 `reactAcc`,依 `REACT` 裡的種類(帽子歪掉、小鳥飛一圈、花掉一片、搖一搖…)隨機挑方向、幅度和時間。用 `requestAnimationFrame` 一格一格改 SVG 的 `transform` 屬性,因為 iOS Safari 對 SVG 元素上的 CSS 動畫不一定會重畫。帽子類(`hidesBump`)戴著時不畫腫包。

## 14. 多語系(中文 / 日本語 / English)

- **語言:** 設定裡存了 `lang`(`zh` / `ja` / `en`)就用它;選「自動」時看 `navigator.languages`,`zh*` 中文、`ja*` 日文,其他一律英文。換語言時直接重新載入頁面(坐禪中就等下次打開)。
- **中文就是 key:** 程式裡畫面上的中文都包在 `tr('…')` 裡,`tr()` 到 `I18N[LANG]` 查譯文,查不到就用中文原文。變數用 `{0}`、`{1}` 填入,英文的單複數寫成 `{0|round|rounds}`,依數字是不是 1 選字。
- **頁面上的字:** `body.html` 和 SVG 裡寫死的中文由 `translateDom()` 在啟動時換掉。元素裡的字如果夾著 `<b>`、`<small>` 這類行內標籤,就整段 `innerHTML` 一起翻,日文、英文才能調換語序;不然就一段一段文字節點翻。`aria-label`、`title`、`placeholder` 也會翻。
- **例外:** 掛軸、印章、木牌上的漢字是畫面的一部分,英文版照樣用漢字(收藏冊裡另附英文意思),日文版換成新字體(静、一期一会),收藏冊裡附讀音(`yomi`)。CSS `content` 裡的「為什麼?」由 CSS 變數 `--why` 帶入。英文版把中日文用的字距拿掉。
- **使用者自己的資料不翻:** 存在紀錄裡的事項名稱(例如「工作」)是使用者輸入的,換語言也照原樣顯示。
- **不變的:** 主畫面上的 App 名稱(`manifest.webmanifest` 只能有一種)和分享預覽都是中文。

## 15. 測試方式

`tests/` 裡是用 Playwright 寫的端對端測試,跑在 Node 內建的測試框架上(`npm test`,也就是 `node --test 'tests/*.test.mjs'`),一次只跑一個檔案。

| 檔案 | 測什麼 |
|---|---|
| `build.test.mjs` | `index.html`、`soundlab.html` 跟 `src/` 重新組出來的完全一致 |
| `onboarding.test.mjs` | 第一次來的介紹(住持拿著香板)、必點的導覽(點框外不前進、點了會打開面板)、略過開場、鍵盤操作、老使用者的導覽、禪堂物件和設定裡的入口 |
| `plan.test.mjs` | 自訂數字超出範圍、逐項改設定、「改設定」只在第一炷前出現、略過開場沿用上次設定 |
| `sitting.test.mjs` | 請打時泡泡和「啪!」的位置、煙跟著香、數字字體、暫離暫停與續算、暫離中出堂、第一次被打的暫離提示 |
| `break.test.mjs` | 在背景時休息結束會發通知、回來時說超時幾分鐘 |
| `journal.test.mjs` | 每日目標達成、分享圖是 1080 × 1350 的 PNG、第一次蓋章的提示、圖例對齊、統計的線香與籤紙、只有未坐滿紀錄時的被打數、各種情況的住持評語 |
| `collect.test.mjs` | 從紀錄算出已拿到的收藏、還差多少;換掛軸和配件會畫進禪堂並在重新整理後保留;坐禪中不能換;第一炷坐滿得到「忍」和葉子並由住持送出;老使用者只導覽一次收藏冊;窗景跟著季節、兩扇窗的彩蛋;備份帶著掛軸和配件(含 v17 以前的單一配件);三格配件同時戴、再點拿下;被打時配件才有反應、帽子蓋住腫包 |
| `i18n.test.mjs` | 程式裡每個 `tr()` 都有日文、英文,而且 `{0}` 和 HTML 標籤一致;日文、英文模式下打開每個面板都沒有剩下中文;依手機語言自動選、設定裡手動切換 |
| `ui.test.mjs` | 沒有點按高亮和選字、標題列只有齒輪、天數章不被切掉、淺色 / 深色和窄螢幕不出錯也不超出畫面 |

`tests/helpers.mjs` 提供的作法:

- **伺服器:** 每個檔案用 `python3 -m http.server` 在隨機埠開 repo,因為 Service Worker 和通知 API 只在 `http://` 下啟用。
- **時間:** `addInitScript` 包住 `Date.now`,加上可調的偏移量 `window.__skew`,就能瞬間「快轉」25 分鐘。App 的計時都是算結束時間點,所以快轉後下一次 `tick()` 就會生效。
- **離開頁面:** 覆寫 `document.hidden` / `visibilityState`,`window.__hide(true/false)` 再送出 `visibilitychange`,模擬切到別的 App 再回來。
- **通知:** 無頭瀏覽器沒辦法真的顯示通知,所以把 `ServiceWorkerRegistration.prototype.showNotification` 換掉,只把標題和內容記到 `window.__notes`。
- **一次性說明:** 預設把導覽、開場說明、暫離說明等標成「已看過」,每個測試只跑它關心的那一段;要測那些說明時再把對應的 key 拿掉。
- **等待:** 對話是一個字一個字打出來的,選項要等打完才出現,所以測試一律等「選項出現」或「整句文字出現」,不用固定秒數。
