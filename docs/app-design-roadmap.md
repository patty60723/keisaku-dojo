# 香板禪堂｜全 App 設計與體驗改造總計畫

> 狀態：規劃基準（2026-11-17）。本文件是設計路線圖，不代表所有提案已核准實作。  
> 主要原則：**原始目標是整個 App 的 UI/UX、視覺美術、角色與互動體驗全面提升；Round 1–5 只是先完成住持與正式版整合，並非整體改造結束。**

## 0. 使用規則：先讀 GitHub，再做下一輪規劃

每次規劃、提出 Claude Code prompt 或修改本專案前：
1. 先確認 `main` 最新狀態、開啟中的 PR/Issue、README 與本文件。
2. 讀取 `docs/round5-acceptance.md`、`docs/round5-integration.md`、`docs/round4-closeout.md`，以及該任務相關的規格、測試和設計資產；不能只靠聊天摘要。
3. 對照「已驗收不可隨意改動」與「待審查」項目。任何與既定決策衝突的提案，要先列出差異並取得使用者確認。
4. 先做現況盤點和整體方案，再按優先順序實作；不要因局部問題反覆微調、忽略整個 App。
5. 每輪完成後更新此路線圖的狀態、決策、PR/commit、驗收與未測項目。**GitHub 是持續維護的專案記錄，不是一次性 prompt。**

## 1. 專案願景與設計原則

- 《香板禪堂》是一款以禪堂、麻糬與持香板住持為核心的專注／坐禪體驗；目標是有辨識度、溫暖、有幽默感、安靜而完整的產品。
- 不只改善住持：**場景、麻糬、整套 UI、報到、坐禪、分心提醒、休息、結算、坐禪帳、收藏冊、設定、導覽、多語系與不同手機尺寸**都要納入整體審查。
- 優先考慮視覺一致性、資訊層級、情緒節奏、操作清楚、易讀與可及性；不是為填滿空間而新增裝飾。
- 保留經驗證的遊戲邏輯與既有成果；美術改動需比較前後畫面，不可無意破壞動畫、巡堂、計時、資料與離線能力。
- 每一輪採「全面盤點 → 問題分級 → 設計方向／候選 → 使用者確認 → 分批實作 → 回歸驗收」，避免無限微調。

## 3. Round 6：全 App UI/UX 與美術改造（下一個主要工作）

**Round 6 的範圍是整個 App，不是只做住持，也不是只有一份報告。** 報告是先行階段，後續應在確認方案後分批實作與驗收。

### 6.1 現況盤點（先做，不直接改程式）

- 以 `main` 正式版為準，擷取完整手機畫面與關鍵狀態：首次使用／導覽、報到、開始坐禪、專注中、分心／香板提醒、暫離／回座、休息、多炷、提前出堂、完成結算、坐禪帳、收藏冊、設定、深淺色與多語系。
- 盤點所有可見元素、操作入口、狀態轉換、文字及視覺層級；檢查小螢幕、較高螢幕、橫向、字體放大與安全區域。
- 與既有設計、測試、Round 5 截圖對照；將實際觀察、推測、已知限制分開記錄。

### 6.2 全面設計審查（產出優先順序）

1. **整體美術與視覺語言**：色彩、材質、線條、字體、光影、圖示、元件一致性，禪意與幽默是否協調。
2. **禪堂場景**：窗、榻榻米、香案、道具、光影、構圖、角色與場景融合；尊重已定案的 D 舞台比例。
3. **麻糬及其他角色元素**：造型、表情、互動反應與住持的風格一致性；住持已驗收部分原則上不重畫。
4. **全套 UI**：計時器、主要／次要按鈕、狀態提示、對話框、文字層級、設定、導覽、深淺色、可點範圍。
5. **完整流程與情緒節奏**：報到 → 坐禪 → 提醒 → 暫離／休息 → 結算，是否自然、易懂且有回饋。
6. **坐禪帳與收藏冊**：資訊結構、瀏覽、完成感、視覺品質與全 App 一致性。
7. **動畫／互動一致性**：不只住持；轉場、回饋、減少動態效果與效能。
8. **無障礙與響應式**：對比、字體放大、操作區、手機橫向與安全區域。

每個問題附上：截圖／位置、使用情境、影響、嚴重度（P0 阻斷／P1 明顯／P2 可改善）、推薦方向、是否碰到鎖定成果、驗收方法。不要因為可改就改。

### 6.3 設計系統與候選提案（需使用者確認）

- 先提出整體設計方向、色彩／字體／元件／場景的協調規則及代表性畫面 before/after。
- 將「必要修正」「值得改善」「可留到後續」分清楚，避免每個細節都變成獨立一輪。
- 使用者先核准方向與優先級，再進入程式修改；不得自行推翻已驗收住持或方案 D。

### 6.4 分批實作與驗收

- 按跨畫面一致性與優先度分批，例如設計 token／共用元件、主要坐禪流程、紀錄收藏、設定與導覽；實際切分依審查結果決定，不預先假定一定要重畫所有畫面。
- 每批有對照圖、功能與視覺回歸、行動裝置尺寸檢查、已知限制；保留原有資料與離線功能。
- 所有批次完成且使用者驗收後，才稱 Round 6 結案。

**Round 6 第一個交付物**：完整現況截圖索引＋UI/UX／美術審查報告＋分級改善清單＋提案優先順序；**先不改程式**。此交付物不是 Round 6 的最終終點。（2026-11-17 已完成，Q1–Q6 方向已確認；6-1 已驗收合併，見 6.5。）
