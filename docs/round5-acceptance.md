並把坐禪畫面的版面定為「方案 D」。整合設計與狀態對照表在 [`round5-integration.md`](round5-integration.md)，

本文件的每一項都標成三種之一：

- **PASS**：已實際驗證。除非另外註明，都是在這個專案的無頭 Chromium（Playwright）裡驗證的，**不是真實手機**。

- **KNOWN LIMITATION**：已知、並且已接受的限制。

## 2. 方案 D：最終版面決策

**問題：** 原本禪堂容器會撐滿畫面剩下的高度（`flex: 1 0 auto`）。報到時對話框佔掉一部分，坐禪開始後對話框隱藏，
舞台就往下長出一大片榻榻米（390 寬時 285 → 436 px），角色卻都在上半部。

**比較過的方案：**

| 方案 | 做法 | 結果 |
|---|---|---|
| A（原本） | 舞台撐滿剩餘高度 | 坐禪時下方大片空榻榻米；開始坐禪時舞台 +151 px |
| B | 坐禪時舞台最多 1.35 倍場景高度 | 空白移到舞台與合掌請打之間 |
| C | 所有階段固定 1.2 倍 | 同上，空白更多 |
| **D（選定）** | 舞台用自己的高度，操作區緊接在後 | 舞台、合掌請打、計時卡連續排列 |

**D 的規則**（`src/dialog.css` 最後一段）：

- 舞台不撐滿畫面：直向時高度是場景高度的 1.25 倍，每個階段都一樣；橫向拿著手機時不加地板。
- 合掌請打與計時卡以頁面原本的 14 px 間距接在舞台後面；不把計時卡推到手機底部；頁面比畫面長時自然捲動。
- 結算卡和 SVG 放在同一個 grid 格子裡，舞台高度取兩者較高的，卡片不會被裁切。
- 沒有用負 margin、絕對定位或依手機高度寫死的位移。

**選 D 的原因（使用者決定）：** 不為了填滿手機而拉長舞台或製造空白；報到與坐禪切換時舞台高度穩定；
接受高螢幕手機在計時卡下方保留自然留白。這項決策已定案，`?stage=` 切換參數與 A／B／C 的候選規則已從程式移除。

比較圖、各尺寸截圖與測量數據保留在 [`design/round5/stage/`](../design/round5/stage/)（A／B／C）
與 [`design/round5/stage-d/`](../design/round5/stage-d/)（A／B／C／D）。
