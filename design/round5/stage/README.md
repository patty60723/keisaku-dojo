# Round 5 坐禪舞台高度：候選 B、C

預覽（同一個 `index.html`，只差網址參數；沒有參數就是目前已接受的版本）：

| 版本 | 網址參數 |
|---|---|
| A（目前） | `index.html` 或 `index.html?stage=a` |
| B 適度縮短 | `index.html?stage=b` |
| C 統一高度 | `index.html?stage=c` |

參數會記在這個分頁（`sessionStorage`），重新整理後仍是同一個候選；用 `?stage=a` 回到目前版本。

## 原因（依程式碼）

- 禪堂畫面是 `#stage`，一張 viewBox `400 × 280` 的 SVG，`width: 100%; height: auto`。**它在報到與坐禪時都一樣大**，viewBox、比例與座標都沒有變。
- 外面的容器 `.stage-wrap` 是 `flex: 1 0 auto`（`src/dialog.css`），而 `body` 是 `min-height: 100dvh`、`.app` 是 `flex: 1`、計時卡 `.panel` 是 `margin-top: auto`。所以容器會長高，吃掉畫面剩下的高度。
- 報到時對話框（`#dialog`）佔掉一部分高度；坐禪開始時對話框隱藏，容器就長到把那段高度補滿。`glideFloor()`（`src/app.js`）只是讓這個變化用 0.5 秒滑過去。
- SVG 下面那段榻榻米不是 SVG 的一部分，是容器的 CSS 背景（`repeating-linear-gradient`，週期與 SVG 的織紋相同，所以接得起來）。這是 v17 起的既有版面，不是 Round 5 造成的。

## 下方延伸區有沒有被用到

| 項目 | 位置 | 用到延伸區？ |
|---|---|---|
| 巡堂路徑 | 最前方的路點 LF、RF 在 Round 4 座標 y 282，換成這裡是 y 265；腳下陰影到 y ≈ 270 | 否，都在 280 以內 |
| 香板提醒 | 立點 (132, 254) → 這裡 y 237 | 否 |
| 前景圖層 | `#monkNear`、`#monkFxSlot` 都在 SVG 裡 | 否（SVG 外的部分本來就會被裁掉，也沒有東西畫在那裡） |
| 對話泡泡、啪、星星、木牌與掛軸的點擊範圍 | 都用「SVG 單位」從上往下定位 | 否 |
| 事件提示（toast） | 舞台頂端 | 否 |
| 結算卡 `.result` | `position: absolute; inset: 0`，蓋滿整個容器 | **是**：卡片在容器裡置中，需要容器夠高 |

所以縮短容器不會改到任何座標、比例或圖層；唯一要處理的是結算卡。兩個候選都讓結算卡出現時容器照舊長高，卡片不會被裁掉。

## 實測（容器高度 ÷ SVG 高度）

| 尺寸 | A 報到 | A 坐禪 | B 坐禪 | C 報到 = 坐禪 | SVG 大小（A、B、C 相同） |
|---|---|---|---|---|---|
| 320×640 | 1.01 | 1.31 | 1.29 | 1.21 | 270 × 189 |
| 390×844 | 1.20 | 1.83 | 1.36 | 1.21 | 340 × 238 |
| 412×915 | 1.38 | 1.98 | 1.36 | 1.21 | 362 × 253 |
| 844×390 | 1.01 | 1.01 | 1.01 | 1.21 | 538 × 377 |

開始坐禪時容器高度的變化：A 在 390 與 412 都 +151 px；B 在 390 +38 px、412 −6 px、320 +53 px；C 一律 0。原始數字在 `measurements.json`。

## 方案

### B 適度縮短（`?stage=b`）
- 坐禪、暫離、休息時，容器最多長到 SVG 高度的 1.35 倍（下方榻榻米最多是場景高度的 35%）。報到時不變。
- 優點：報到畫面完全不變；坐禪時仍有一點地板延伸，跟報到的感覺接近；開始坐禪時只有小幅滑動。
- 缺點：
  - 剩下的高度變成舞台與「合掌請打」之間的一段頁面底色：390 寬約 120 px、412 寬約 165 px（320 寬幾乎沒有）。
  - 不同手機報到時的比例本來就不同（1.01–1.38），所以 B 在 412 寬時會比報到略短一點（−6 px），在 320 寬時比報到長。

### C 統一高度（`?stage=c`）
- 所有階段都用同一個高度：SVG 高度的 1.2 倍（約 390 寬手機報到時的比例）。
- 優點：開始坐禪時舞台完全不動；每支手機的構圖都一樣。
- 缺點：
  - 報到畫面也跟著改了：320 寬時舞台比現在高，報到時頁面多 38 px 要捲；412 寬時比現在矮（1.38 → 1.21）。
  - 坐禪時空出來的頁面底色比 B 多：390 寬約 160 px、412 寬約 205 px。
  - 844×390 橫向時，報到與坐禪的頁面都多了約 75–80 px 要捲。
- 結算卡出現時容器仍會長高（否則卡片會被裁掉），所以結算那一刻舞台會變高。
- C 可以在不裁切、不改角色座標的前提下成立。

## 兩個方案都遵守的
- 不改 SVG 的 viewBox、比例與任何物件或角色的座標；住持、巡堂姿勢與 Round 3.5 提醒都不動。
- 不縮放 SVG，角色大小在三個版本都相同（見上表的 SVG 大小）。
- 「合掌請打」和計時卡留在畫面下方、拇指搆得到的地方；空出來的高度在舞台與它們之間。
- 寬螢幕橫向版面（寬 ≥ 900 px）不受影響。
