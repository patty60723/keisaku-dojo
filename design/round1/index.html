香板禪堂 UI/UX、角色與動畫重設計

第一輪交付：現況審查、問題清單、新的 Art Direction，以及首頁／專注中／結算與角色的可互動原型。正式版完全沒有改動，所有內容都在 design/round1/，等方向確認後才進入實作。

開啟可互動原型原型＋對照 v20角色表

原型上方的深色列是原型控制列，不屬於設計：可切換畫面、日／黃昏／夜、低效能、減少動態，以及觸發「被打」「連續分心」「快轉到結束」等示範。寬螢幕勾選「對照 v20」會左右並排，手機上則是 A/B 切換。

這一輪的結論，用三句話說：
  1. v20 的角色與世界觀很完整，問題不在「缺東西」，在層次：場景是平面的，UI 每一塊都有框，紅色出現的次數太多，主要動作沒有被凸顯。
  2. 首頁應該是「場景 → 開始坐禪 → 這次的計畫 → 其他」，回訪者一鍵就能開始；專注中只留時間；結算變成一段可以略過的小儀式。
  3. 動畫要從「位移」升級為「表演」：預備、停頓、命中、回彈、收尾。並且分三個層級，同一時間只會有一個大事件。

01現況審查報告

以下結論都來自閱讀 src/ 的程式碼與實際截圖。標記 程式碼確認 的是我在原始碼裡看到的事實；標記 需裝置測試 的是合理推論，必須在你的 Android 手機與 iPhone 上驗證才能下結論。

做得好的，要保留
  • 計時用時間戳記（P.end = Date.now() + …，app.js:1396；tick() 用 P.end - Date.now()），不依賴畫面幀數。背景、降頻都不會讓時間跑掉。
  • 已經尊重 prefers-reduced-motion（app.js:3，各動畫入口都有檢查）。
  • 表情動畫改寫 SVG transform 屬性（animateFace），在 iOS 上穩定。新方案沿用這個作法。
  • 回訪者已經可以兩步開始：「跟上次一樣」→「準備好了」（onboarding app.js:942、readyCheck app.js:1128）。
  • 新手導覽會實際點亮熱點並要求點擊（tour() app.js:1967），學習效果比文字說明好。
  • 世界觀一致：悟之窗／迷之窗、坐禪帳、堂規、收藏冊都是場景裡的實物。
主要問題
  • 場景是平面的：牆面 y 0–176、榻榻米 y 176–280 都是平塗，角色沒有接觸陰影，看起來像貼紙浮在地上。
  • UI 太多框：對話卡、計時卡、按鈕全部有 1.5px 邊框，視覺重量平均，眼睛找不到主角。
  • 紅色太多：朱紅用在警示文字、連續天數徽章、被打的 toast、印章，降低了「被打」與「印章」的戲劇性。
  • 首頁沒有「開始」按鈕：大大的 25:00 看起來可以按，但真正的入口是住持的問題與選項。
  • 專注中地板被撐高：手機直式時舞台吃掉大半個螢幕，計時被推到最底下。
  • 結算是靜態卡片：場景被模糊掉，麻糬看不見，坐完一炷的成就感沒有被表演出來。
  • 打擊缺少表演節拍：有舉板與 160ms 停頓，但沒有「麻糬察覺」、沒有 hit-stop、沒有回彈與收尾。

03新的 Art Direction

Cozy Zen × Character Animation × Japanese Illustrated Diary
像一本手繪的禪堂日記：紙是和紙，墨是暖墨，光從窗戶進來，角色站在地上、有重量。

場景分層

  1. 背景：牆、梁、柱、兩扇窗、床之間（tokonoma）。床之間是新增的凹室，給房間一個「更深的後面」，掛軸與香爐移進去。
  2. 中景：透視榻榻米。縫線向消失點 (200, 40) 收斂，三排間距由遠而近 30 → 46 → 38；牆根加一條 18 單位的 AO 漸層。
  3. 角色：住持、蒲團、麻糬。蒲團有座布團＋圓柱體兩層；麻糬坐下時下沉 2 單位，前緣蓋過身體底部，看起來真的坐進去。
  4. 前景：底部一條緣側木框＋柔和暗角（vignette），把視線收向中央。
光分成五種，各自獨立
  • Ambient：整體色溫。黃昏用 multiply 暖色 16%。
  • Window light：窗戶光柱＋地上光斑。白天柔白、黃昏長而暖（光斑落在麻糬身上）、夜晚從方窗來的冷月光。
  • Local light：夜間行燈的暖光、香頭的小火點。
  • Character light：麻糬的徑向漸層體積＋迎光側的 rim light（黃昏在左、夜晚在右）。
  • Contact shadow：每個角色腳下模糊橢圓；麻糬跳起時陰影縮小變淡。

低效能模式：拿掉所有 feGaussianBlur、灰塵粒子、畫面晃動與 backdrop-filter；陰影改成不透明度 70% 的實心橢圓。結構與光的方向都不變。

04首頁／專注中／結算 重設計

首頁：3 秒內看懂

閱讀順序被設計成：場景（我在禪堂）→ 開始坐禪（唯一的藍色大按鈕）→ 這次的計畫（讀書・25 分 × 2 炷）→ 次要資訊（今日分鐘、本週來堂）。

  • 三層設定：快速開始＝直接按「開始坐禪」，沿用上次計畫（1 次點擊，現在是 2 次＋等打字）。調整本次＝原地展開三排 chip（做什麼／一炷多久／坐幾炷），不跳頁。進階設定＝偵測方式、鐘聲、每日目標，收在「調整本次」最下面的連結與齒輪裡。
  • 住持的話變成場景下緣的一條紙片，跟場景連在一起，而不是另一張獨立卡片。回訪者的問候直接顯示（淡入 200ms）；打字動畫只保留給新手開場與特殊事件，且點一下就跳完。
  • 熱點可發現性：進場時名牌浮現 2.6 秒（前 3 次造訪，之後只在有新內容時）；長按場景任何地方會顯示全部名牌；有新收藏時在收藏冊旁放抹茶色小點，脈衝 3 次後停止。
  • 連續天數改成「本週來堂 4 天」，不顯示紅色徽章，斷掉也不提醒。

專注中：只留時間

  • 舞台固定 4:3；多出來的高度留給時間，大字 76px 置中，下面一條細細的香（進度）與「讀書・第 1 / 2 炷」。
  • 標題列淡到 35%；「暫離」「出堂」是無底色的 ghost 按鈕。
  • 偵測說明改成中性的 ⓘ 這次的偵測：切出畫面，點開才有解釋，不再有紅字。
  • 「合掌請打」變成場景右下的半透明膠囊，不與時間搶位置。
  • 手機螢幕朝下模式：畫面多半不會被看到，所以拿起手機的那一刻才是重點。建議第 2 輪設計「拿起來」的瞬間畫面：住持已經轉頭看你、時間清楚可見。

結算：一段可以略過的小儀式

  1. 鐘 0 ms：一聲鐘，香頭熄滅。
  2. 麻糬 700 ms：睜眼 → 伸懶腰（拉長 1.10 / 0.94，雙手舉高）→ 彈回 → 滿足臉。
  3. 住持 ≈1.8 s：轉向麻糬、瞇眼笑，泡泡「坐得很穩。」
  4. 紙 ≈2.3 s：和紙（上緣是毛邊）從下方滑上，蓋住舞台下緣 26px，場景不被模糊。
  5. 印 ≈2.9 s：印章從 1.6 倍、−14° 落下壓到 0.94 再回 1.0；紙面震一下、輕震動 12ms。唯一的朱紅。
  6. 紀錄 ≈3.3 s：今日分鐘、本週來堂、被打次數依序數上來。
  7. 解鎖 ≈5 s：只有在有新東西時出現：新收藏卡片帶 overshoot 滑入。
  8. 動作 ≈5.6 s：公案淡入，然後「收下」「再一炷」「分享」。

右上角「略過 ›」或點舞台任何地方，立刻跳到最終狀態。減少動態模式下全部直接顯示終態。從背景回來時也直接是終態，不會重播。

05麻糬與住持角色規範

麻糬

造型
  • 大福輪廓，高 68、寬 72，底部最寬，表現重量（舊版是蛋形，底部收窄）。
  • 路徑：M-34 0 C-38 -10 -36 -30 -26 -48 C-18 -62 -8 -68 0 -68 C8 -68 18 -62 26 -48 C36 -30 38 -10 34 0 C22 4.5 -22 4.5 -34 0 Z
  • 五官偏下：眼睛 y −30、x ±11；嘴 y −21；腮紅 (±20, −22)。fx（汗、Z、愛心、星）在頭的右上 (24–36, −40 – −64)。
  • 體積：徑向漸層（亮點在左上 36%/26%）＋底部陰影新月＋左上高光；黃昏／夜加 rim light。
  • 手是小圓「nub」，依姿勢移動：side（站）、lap（坐禪手印）、gassho（合掌）、rub（摸頭）、cheer（舉手）、tuck（預備蜷縮）。
骨架（rig）
  • root translate（位置）→ lean rotate（以底部為軸，傾斜與跳躍高度）→ squash scale（以底部為原點，壓扁不會離地）。
  • 陰影獨立於 lean：跳得越高越小越淡（k = 1 − lift/70）。
  • 眼睛群組另外有 blink（scaleY）與 gaze（±3 位移）。
  • 呼吸（L1）：坐著 1.3 rad/s、幅度 1.4%；站著 2.2 rad/s、0.8%。
  • 壓扁體積守恆的近似：sx ≈ 1 + (1 − sy) × 0.65。

表情規格（12 種）

共通規則：切換表情一律用 70ms 眨眼遮住（先閉眼、換、再睜眼），避免五官突然跳動。fx 永遠畫在配件之上。

住持

造型

  • 嘴：smile／flat／laugh／o／sip。

排程規則：從「情境允許＋冷卻已過」的候選中，取最高優先級，並以 35% 機率混入較低優先的，避免太規律。L3 事件進行中一律不排。原型「角色」分頁的「自動排程」會把每一次決定寫進紀錄。

配件，特別是身上的衣物

  • 軟配件（衣物、圍巾本體、腰帶）：以麻糬身體做 clipPath，放在 squash 群組裡面。所以會跟著壓扁拉長，衣襬永遠不會超出輪廓；外框在衣物之後重描一次，邊緣乾淨。
  • 衣物結構（以浴衣為例）：衣領是兩條相交的弧線，在中線 y −10 交會，左襟壓右襟（觀者看到右側那片在上）；白色半襟 3px；腰帶 y −9 到 −2；袖口＝手 nub 換成布料色（--sleeve）並加一條袖口線；下襬就是身體底線。
  • 垂墜物（圍巾尾巴、流蘇）：在 clip 之外，掛在固定錨點，旋轉角跟著垂直速度與身體傾斜延遲（follow-through，lerp 0.12）。
  • 硬配件（帽子、斗笠、花）：放在 squash 外面，只跟頂點位置 −64 × sy 與傾斜（延遲 0.18），寬度只跟 50% 的 sx，形狀不被壓扁。
  • 臉部 fx 永遠畫在硬配件之上（延續 v20 的 .fx 層規則）。

06動畫規範與狀態轉換

三個層級

層級內容規則
L1 環境呼吸、眨眼、香煙飄、窗光灰塵、住持站立的微晃永遠在跑、不等待、幅度 ≤ 2%；減少動態時停止；hit-stop 時凍結

跳上蒲團

狀態轉換

  • 每個狀態進入時先 flush 前一個狀態的所有 tween（直接套用終值），不留殘影。
  • 打擊只能從「專注」進入，結束一定回到「專注」；結算期間不可能被打。
  • 從背景回來（visibilitychange）：所有進行中的動畫直接跳到終態，不補播。

技術規範

做法
  • 單一 requestAnimationFrame 迴圈；每幀寫入 SVG transform 屬性（不是 CSS transform），iOS Safari 一致。
  • tween 以 performance.now() 計算進度，掉幀只會少畫幾格，不會變慢。
  • 計時仍以 Date.now() 的結束時間戳記為準，與動畫完全脫鉤。
  • hit-stop 用「凍結到某時間點」實作，不阻塞計時。
  • UI 小動畫（紙、印章）可以用 WAAPI；角色一律走 rAF。
  • 音效用 WebAudio 即時合成（鐘、木聲、蓋印），不需要額外檔案；正式版可沿用 v20 的音色。
降級
  • prefers-reduced-motion：沒有跳躍弧線、晃動、粒子、呼吸；表情仍會換；儀式直接顯示終態。
  • 低效能（自動偵測：連續 2 秒 < 40fps，或手動）：去 blur、去 blend、去粒子、去 backdrop-filter。
  • Android Chrome：navigator.vibrate 可用；音效需要使用者手勢後才能開始。
  • iOS Safari：沒有震動，只靠聲音與畫面；PWA 背景計時以通知補足（v20 已有）。
