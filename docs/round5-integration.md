# Round 5 整合設計：Round 4 住持進正式版

目的：讓正式版 `src/`（`index.html`）使用 Round 4 已驗收的住持（Round 3.5 造型與香板提醒、候選 B 新視角、自然巡堂）。
正式版的計時、炷數、休息、暫離、偵測、紀錄、收藏與文案都沿用，不另寫一套。

## 1. 正式版與 Round 4 原型的差異（整合前）

| 項目 | 正式版（`src/app.js`） | Round 4 原型（`design/round4/`） | 整合後 |
|---|---|---|---|
| 場景 | `#stage` viewBox 400×280，麻糬坐在 (200, 240) | 400×300，麻糬在 (206, 257) | 正式版場景不動；住持放在 `translate(-6 -17)` 的群組裡，沿用 Round 4 座標，麻糬在兩邊座標系中重合 |
| 住持繪製 | 舊版住持（固定 SVG，`#monk` + `#stickLayer`） | `MonkActor`（Round 3.5 `MONK4.art` + `KEISAKU_ANIM`）＋ `NaturalPatrol`（候選 B 姿勢庫） | 舊住持刪除，改用 Round 4 模組 |
| 移動 | 每幀朝 `M.tx` 直線移動，只左右走 | 沿安全路點的路徑，景深縮放、圖層依深度 | 沿 Round 4 安全路徑；正式版的「對話時站旁邊」「休息喝茶」改成路徑上的兩個停留點（HO、TE） |
| 香板 | 平常放在右柱，坐禪時去拿、結束放回 | 住持一直拿著（香板不換手） | 住持一直拿著；右柱上的香板不再顯示（見 §4） |
| 分心來源 | 平衡儀（拿起、每 20 秒補打）、離開畫面（≥ 2 秒、≥ 90 秒再補一下）、合掌請打 | 同樣的事件（模擬） | 偵測程式與門檻不改，只改事件送去哪裡 |
| 計數 | 香板命中時 `P.hits++`、`P.roundHits++` | 正式版規則：命中時；Round 1 規則：合併的在發生時 | 事件成立時計數；演出合併（§3） |
| 演出佇列 | `enqueue(strike)`，每個事件一次完整打擊，依序排隊 | 正式版規則：排隊；Round 1 規則：合併 | 不排隊重播：提醒進行中再來的事件併入當次提醒 |
| 計時 | `P.end`、`tick()` 每 250 ms | 原型自己的 `P` | 只有正式版的 `P`、`tick()`；住持只讀狀態 |
| 動畫時鐘 | `requestAnimationFrame` 的 `frame()`，dt ≤ 50 ms | 同（巡堂、演出各有自己的時鐘，只在有影格時前進） | 正式版的 `frame()` 呼叫 `NP.update` 與 `K.render`，一個迴圈 |

## 2. 狀態對照表：每個階段住持做什麼

正式版階段 `P.phase` 是唯一的狀態來源。住持由一個控制器 `Monk`（`src/monk/director.js`）帶，任何時候只有它改住持的位置與動畫：

| `P.phase` | 住持 | 分心事件 | 平衡儀監聽 |
|---|---|---|---|
| `idle`（報到、對話） | 走到 HO（麻糬左邊）面向麻糬；導覽與介紹時也在那裡 | 不處理 | 不判斷（`Mo.base` 為 null） |
| `settle`（落座 3 秒、回座） | 走到 BL，開始巡堂前的位置 | 不處理 | 等靜止後記基準 |
| `focus` | 自然巡堂；有事件就提醒 | 處理 | 判斷 |
| `leave`（暫離） | 停止巡堂：走到 HO（麻糬站著時的位置）面向麻糬站著（若正在提醒，先演完） | 不處理 | 不判斷 |
| `break`（休息） | 走到 TE（香案旁）面向左喝茶，「喫茶去～」 | 不處理 | 不判斷 |
| `ready`（休息後對話） | HO | 不處理 | 不判斷 |
| 出堂（`quitEarly` → `idle`） | 提醒立即中止，住持直接回到垂放姿勢，再走去 HO | 不處理 | 停止 |
| 計時完成（最後一炷） | 正在演的提醒演完，然後結算卡 | 不處理 | 停止 |

## 3. 分心事件與連續分心（本輪採用的混合規則）

```
偵測（不改）            事件成立                         演出
平衡儀：拿起 ───┐
平衡儀：每 20 秒 ─┤      P.phase === 'focus' 才成立           沒有提醒在進行 → 開始一次提醒
離開畫面 ≥ 2 秒 ──┼──→  成立：P.hits / P.roundHits /  ──→  （停下 → 嚴肅、轉向 → 安全路徑到立點 →
離開 ≥ 90 秒補一下 ┤      P.todayHits 立刻 +1               Round 3.5 完整提醒 → 回巡堂）
合掌請打（手動） ──┘      手動：只 P.asks +1（命中時）       提醒進行中 → 併入當次提醒，不重播
```

- 事件成立的時候就記錄一次；香板命中只是演出。一次提醒可以對應多個事件。
- 去抖動、冷卻沿用偵測端原有的：拿起要干擾 0.6 秒、放回才會再算下一次拿起、拿著不放每 20 秒一次、離開畫面一次回來只算一次（≥ 90 秒算兩次）。
- 提醒進行中（包括走向立點途中）再成立的事件：計數，顯示原本的提示文字，但不再排隊；這次提醒演完時說「又分心了 N 次」。
- 合掌請打：不算被打；提醒進行中按了不處理（正式版本來就是這樣）。
- 不成立：暫離、休息、落座、對話、出堂後、計時完成後。
- 佇列最多只有「目前這一次」，不會無限累積。
- 紀錄格式不變：`hits` 仍是這一炷被打的次數，意思是「有效分心事件數」。正式版以前每個事件都會打一下，所以舊紀錄的數字和新規則一致，不需要遷移。

## 4. 已知的呈現差異（不影響規則）

- 香板一直在住持手上（Round 4 驗收的設計：香板不換手、不放下）。右柱上的香板與「去柱子拿香板 / 放回」的動作拿掉；開場介紹「這支香板」時住持一樣拿著它。
- 察覺（嚴肅神情、轉向麻糬）在巡堂中發生，舉板在立點開始（Round 4.2B 已驗收）。
- 一次提醒對應多個事件，所以「打了幾下」的畫面次數可能少於計數。
