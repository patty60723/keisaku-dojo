# 技術文件

這份文件只寫技術細節與演算法:程式怎麼組起來、各個偵測和計算怎麼做、資料怎麼存。
產品行為(對話流程、坐禪帳的規則)寫在 [`onboarding-spec.md`](onboarding-spec.md) 和 [`journal-spec.md`](journal-spec.md)。

## 1. 架構與建置

- 純前端、沒有框架、沒有外部 JS 套件。只從 Google Fonts 載入兩套字型(霞鶩文楷 TC、Fredoka),載不到時退回系統字型。
- 上線的是單一個自帶 CSS / SVG / JS 的 `index.html`,由 `build.py` 從 `src/` 組出來:

  | 檔案 | 內容 |
  |---|---|
  | `src/style.css` | 色彩 token(淺色 / 深色)、版面、禪堂 SVG 的上色 class、計時卡片 |
  | `src/extra.css` | 炷香指示、偵測狀態 |
  | `src/dialog.css` | 對話框、彈出面板(手卷)、坐禪帳、統計、導覽等;後面的規則會覆寫前面的 |
  | `src/body.html` | 頁面結構;`{{SVG}}` 由 `svg.html` 取代 |
  | `src/svg.html` | 禪堂場景(viewBox `0 0 400 280`) |
  | `src/app.js` | 全部程式,包在一個 IIFE 裡 |

- `python3 build.py` 產生 `index.html`;`python3 build.py preview` 產生 `preview.html`(左上角多一個「預覽版」標籤,其餘相同)。
- `python3 build_lab.py` 從 `app.js` 裡 `/*SND-START*/ … /*SND-END*/` 之間的聲音引擎產生 `soundlab.html`,所以試聽台跟 App 永遠用同一份聲音程式。
- `<head>` 裡有一小段同步 script,在第一次繪製前把存好的深淺色套到 `<html data-theme>`,避免閃一下另一個主題。

## 2. PWA 與快取

- `manifest.webmanifest` 的 `id` 寫完整路徑 `/keisaku-dojo/`。寫 `./` 會被解析成網域根目錄,跟同一個 `github.io` 網域上的其他 App 撞 ID。
- `sw.js` 的快取策略:

  | 請求 | 策略 |
  |---|---|
  | 頁面導覽(`mode: navigate`) | 網路優先。成功就以**各自的 URL** 存進快取;離線時先找同一個 URL(忽略 query),再退回 `./index.html` |
  | Google Fonts | 快取優先,存進獨立的 `keisaku-fonts`,不隨版本清除 |
  | 同源的其他檔案(圖示、manifest) | 快取優先 |

  頁面要用各自的 URL 快取,是因為以前全部存成 `index.html`,打開 `soundlab.html` 或 `preview.html` 會蓋掉 App 本體。
- 每次上版把 `VERSION` 加一:`activate` 時會刪掉所有 `keisaku-shell-*` 舊快取,並用 `skipWaiting` + `clients.claim` 讓新版立刻接手。
- `notificationclick` 會把已開著的 App 視窗拉到前面,沒有的話開一個新的。

## 3. 時間與狀態機

### 坐禪的階段

```
idle(報到對話)→ settle(放手機的 3 秒)→ focus → break → ready(對話)→ settle → focus …
                                          ↘ leave(告假)→ settle → focus
最後一炷 focus 結束 → 結算卡 → idle
```

- 所有計時都存「結束的時間點」(`P.end = Date.now() + 長度`),每 250 ms 的 `tick()` 用 `P.end - Date.now()` 算剩下多少。
  頁面被瀏覽器暫停後再回來,時間還是對的,不會因為計時器被節流而變慢。
- 告假時把剩餘毫秒存進 `P.left`,回座並重新放好手機後 `P.end = Date.now() + P.left`。
- 坐禪中用 Screen Wake Lock 讓螢幕保持亮著;切回頁面時會重新申請。

### 住持的動作

- 住持一次只做一件事。打人、拿警策、放回警策這類動作都排進佇列(`enqueue` → `pump`),依序 `await` 執行。
- 佇列空了,就由 `settleMonk()` 依階段決定閒置模式:`patrol`(巡堂)、`host`(站在旁邊對話)、`rest`(去茶几喝茶)。
- 位置在每一幀(`requestAnimationFrame`)朝目標移動,`dt` 上限 50 ms,避免切回頁面時瞬移。走路時身體有上下擺動。開啟系統的「減少動態效果」時,走路不擺動,麻糬跳上蒲團、對話打字、面板的展開收起都直接完成,煙和呼吸的循環動畫也停掉。

## 4. 拿起手機的偵測(平衡儀)

輸入是 `devicemotion` 的 `accelerationIncludingGravity`。iOS 要先 `DeviceMotionEvent.requestPermission()`,而且必須在點擊事件裡同步呼叫,所以放在「準備好了」和「回座」按鈕的處理函式裡。

每一筆讀數 `v = (x, y, z)`:

1. **晃動量** `jerk = |v − lp|`,`lp` 是上一刻的低通結果。
2. **低通濾波(重力方向)** `lp = 0.85·lp + 0.15·v`。
3. **靜止時間**:`jerk > 1.2` 就歸零,否則累加 `dt`(單筆最多算 0.1 秒)。
4. 坐禪開始時,把當下的 `lp` 存成基準 `base`。之後看 `ang = angle(lp, base)`。

判斷:

| 狀態 | 條件 |
|---|---|
| 被干擾的這一刻 | `ang > 20°` 或 `jerk > 3.5` |
| 算拿起來 | 干擾分數 `score` 超過 0.6 秒。干擾時 `score += dt`,沒干擾時 `score −= 0.5·dt`(不低於 0),所以短暫碰到不會算 |
| 算放回去 | 靜止超過 1.5 秒且 `ang < 15°`,或靜止超過 3 秒且手機是平躺的(換一面放也算) |
| 拿著不放 | 每 20 秒再打一下 |

- **落座時:** 倒數 3 秒後,還要連續靜止 0.8 秒才記基準。
- **讀不到感應器時:** 沒拒絕權限,卻從來沒收到 `devicemotion`,就退回只偵測「離開畫面」,計時卡片會顯示「⚠ 只能偵測切出畫面」。
- **放回去之後:** 每次放回去都用新的位置當基準,所以換個角度放也可以。

## 5. 離開畫面的偵測

- 坐禪中 `visibilitychange` 變成 hidden 時記下時間。
- 回來時計算 `away = min(now, P.end) − hiddenAt`:
  - 小於 2 秒:不算
  - 2 秒以上:打一下
  - 90 秒以上:再補一下
- 休息時不偵測。

## 6. 休息結束與通知

- 休息到時間時,`endBreak()` 會看頁面是不是在背景:
  - **在背景:** 標記 `awaitReturn`,用 `ServiceWorkerRegistration.showNotification` 發通知(tag `keisaku-break`、`renotify`),等使用者回來才開始對話。
  - **在前景:** 直接開始對話。
- 回來時算超時 `late = now − 休息結束時間`,滿 1 分鐘就記成 `lateMin`,存進下一炷的紀錄。
- **限制:** 沒有推播伺服器,通知只能在頁面的 JS 還在跑時發出。Android 會節流或凍結背景頁面,所以通知可能晚到或沒有;要準時,得加 Web Push 伺服器排程。

## 7. 聲音(Web Audio,全部即時合成)

- `AudioContext` 在第一次點擊時建立(瀏覽器的自動播放限制)。
- **鐘:** 523 Hz 的正弦波疊上 ×2.42、×4.05、×0.5 的泛音,各自有不同的衰減時間,做出寺鐘的不和諧泛音。止靜三鐘每聲間隔 1.5 秒。
- **噪音底:** 預先產生約 4 秒的白 / 粉紅(Paul Kellet 濾波)/ 棕噪音 buffer,接縫交叉淡化避免喀聲;每一層從隨機位置開始循環,疊在一起時才不會對齊。
- **空間:** 每個聲音事件都經過一個立體聲定位,並分成乾聲和送進殘響兩路。殘響是 `ConvolverNode`,脈衝響應即時產生:3.4 秒的立體聲雜訊,振幅乘上 `(1 − t)^2.8` 衰減(`hallReverb`)。
- **共用工具:**
  - `shape()`:在參數上排一串短的線性斜坡,畫出不規則的包絡線,隨時取消也不會爆音。
  - `wander()`:平滑的隨機漫步。
  - `burst()`:一小段濾波雜訊。
  - `blip()`:一個滑音。
- **背景聲音都是「稀疏事件」,不是連續的雜訊:**
  - **雨:** 每滴是一個很短的共振喀聲(窄頻帶的雜訊在響),不是滑音,滑音聽起來像鳥叫。
    - 音量大多很小(`random³ × 0.4`),5% 機率出現大顆的雨滴。
    - 間隔在 `dropGapMin`–`dropGapMax` 之間;整體雨勢每 4–10 秒在 0.25–1 之間緩慢漂移。
  - **海浪:** 每一波先湧上 2.5–6 秒,湧越久能量越大:落地的碎浪越響(粉紅 + 白 + 棕三層)、泡沫越多、退潮越長(`waveBackMin`–`waveBackMax`)。底下還有一層會自己漂移的遠方浪聲。
  - **森林:**
    - 幾隻鳥:7 種叫法,各自成段地唱
    - 蟋蟀:一聲是 3–4 個高頻脈衝
    - 樹葉:一陣風吹過,帶通雜訊的中心頻率隨風勢起落、從一邊移到另一邊,上面疊著葉子的細碎抖動
    - 一隻青蛙:脈衝串的呱聲,每次從左或右傳來
  - **風鈴:** 6 根音管,D6 E6 F♯6 A6 B6 D7(五聲音階,可以再升 0–2 個八度)。
    - 平常多半只撞一下,偶爾隔一會兒再一下。
    - 起風時,風越大撞越多次、越響(`gustKnocksMin`–`gustKnocksMax`)。
    - 每一下是 2–3 根不同的管子幾乎同時響,不會跟上一下是同一根。
- **和音:** D 大調五聲音階的 5 個開放和弦,每個和弦 9–12 秒,70% 機率換到清單裡的下一個,其餘隨機。每個音依序間隔 0.35 秒進來,2.6 秒淡入、長長淡出;偶爾在上面輕輕點一兩個高音。
- **淡入淡出:** 背景聲音在止靜三鐘敲完後才淡入(約 3.8 秒後),放禪、告假、結束時淡出,休息時不播。
- 可調參數都集中在 `SND` 物件,`soundlab.html` 的滑桿直接改它。

## 8. 畫面座標

- 禪堂是一張 viewBox `400 × 280` 的 SVG,寬度撐滿,高度隨寬度等比縮放。
- 疊在禪堂上的 HTML(對話泡泡、「啪!」、星星、木牌和坐禪帳的點擊範圍)都用「SVG 單位」定位:`.app` 設成 `container-type: inline-size`,一個 SVG 單位 `--u = (100cqw − 3px) / 400`(3px 是外框),例如 `top: calc(var(--u) * 146)`。
  - 不能用禪堂高度的百分比:禪堂容器會長高去填滿畫面,百分比會跟著變。
- **延伸的地板:** 禪堂容器長高時,下面露出的部分用 CSS 背景畫成榻榻米。織紋是 `repeating-linear-gradient`,週期跟 SVG 裡的 `pattern` 一樣是 3 個 SVG 單位,而且都從 y = 0 開始,所以接縫處紋路連續;直線的疊蓆邊放在 68%(x = 272 / 400)。
- **線香計時:** 香長 `44 × 剩餘比例`。火點和煙的位置跟著香頂移動;煙的外層 `<g>` 負責往下移,內層 path 負責飄動,因為 CSS 動畫的 `transform` 會蓋掉 SVG 的 `transform` 屬性。

## 9. 資料儲存

全部存在 `localStorage`,不上傳任何地方。第一次存紀錄時會呼叫 `navigator.storage.persist()`,降低被瀏覽器清掉的機會。

| key | 內容 |
|---|---|
| `keisaku-log-v2` | 坐禪紀錄陣列,一炷一筆(見下) |
| `keisaku-last-v1` | 上次的設定 `{ task, focusMin, rounds, breakMin }` |
| `keisaku-presets-v1` | 常用設定,最多 3 組 |
| `keisaku-opts-v1` | `{ motion, sound, notify, goal, theme, ambient, ambVol, music }` |
| `keisaku-rules-asked-v1`、`keisaku-tour-v1`、`keisaku-leave-told-v1` | 開場說明、導覽、告假說明是否已經講過 |
| `keisaku-tip-journal-v1`、`keisaku-tip-leave-v1` | 「去坐禪帳看看」「可以告假」兩個一次性提示是否出現過 |
| `keisaku-notify-asked`、`keisaku-persist-asked` | 是否問過通知權限、是否申請過持久儲存 |

紀錄一筆:

```js
{ t: 1791275279901,      // 存檔時間(ms),跟 d 一起當唯一鍵
  d: '2026-10-06',       // 當地日期
  task: '讀書', min: 25, hits: 0,
  full: true,            // 有沒有坐滿這一炷(只有坐滿的才蓋章、算連續天數)
  leave: 1,              // 有告假才有
  late: 4,               // 這炷前的休息超時幾分鐘,有才有
  goal: 4 }              // 存檔當時的每日目標,有設才有
```

- **沒存的情況:** 分鐘數為 0 而且沒被打的一炷不存。
- **備份格式:** `{ app: 'keisaku-dojo', version: 2, exported, log, presets }`。
  - 匯入時用 `validEntry` 過濾格式不對的紀錄:`t`、`min`、`hits` 是數字,`d` 是 `YYYY-MM-DD`。
  - 以 `t|d` 判斷是不是已經有了,只加入新的,不會覆蓋或刪除。

## 10. 坐禪帳的計算

- **每天彙總**(`dayMap`):把紀錄依日期合併成 `{ min, hits, full(坐滿炷數), goal(當天最大的目標), tasks }`。
- **印章**(`stampKind`):

  | 條件 | 印章 |
  |---|---|
  | 沒有坐滿任何一炷 | 小紅點(有分鐘數或被打過才蓋) |
  | 坐滿且一下都沒被打 | 不動 |
  | 坐滿,當天 ≥ 75 分 | 合掌 |
  | 坐滿,當天 25–74 分 | 坐 |
  | 坐滿,當天 < 25 分 | 淡淡的坐 |

  每個印章的旋轉角度(±7°)和偏移量(±4)由日期字串的 FNV-1a 雜湊算出來,同一天每次畫都一樣,不同天看起來像手蓋的。
- **連續天數**(`streakInfo`):從今天往回數,每天至少坐滿一炷就算。今天還沒坐不會中斷,從昨天開始數。
- **每日目標達成:** 當天坐滿炷數 ≥ 當天的目標。
- **統計期間:**
  - 七日、三十日:以今天為最後一天,每天一格。
  - 全部:從第一筆紀錄的月份開始每月一格,最多 12 個月。
- **格線值**(`gridValue`):從 5、10、15、20、30、45、60、90、120……分裡,選不超過最大值的最大那一個。圖的頂端是最大值 × 1.15,留空間給籤紙。
- **籤紙定位:** 中心對準那根香,但限制在圖的寬度內;尖角另外限制在籤紙兩端各留 10 px,不會跑到紙外面。
- **住持評語:**
  - 跟「前一段同樣長度的期間」比坐禪分鐘數:多 ≥ 30 分算進步,少 ≥ 30 分用安慰的語氣,其他算差不多。
  - 被打:看每炷平均。比前一段少 0.1 以上說有進步,大於 1.2 提醒把手機放遠(安慰句之後不加這句)。
  - 這段期間之前沒有任何紀錄時不比較。
  - 時間的口語說法(`talkMin`):60 分以下說「N 分鐘」,以上四捨五入到半小時,例如「1 小時半」。

## 11. 分享圖

- 1080 × 1350 的 canvas。
- **禪堂畫面:** 把 SVG 複製一份,逐一把每個元素算好的 `fill`、`stroke`、`opacity`、`display`、字型等寫進 `style`,因為原本的顏色來自 CSS class 和變數,單獨的 SVG 圖片讀不到。接著序列化成 `image/svg+xml` 的 Blob,載入成圖片再畫上 canvas。
- **字型:** 文字用 `document.fonts.load()` 確定字型載好再畫。
- **提前產生:** 結算卡一出現就先產生 PNG,按「分享」時才不會因為等待而失去使用者手勢。
- **分享方式:** 支援 `navigator.canShare({ files })` 就叫出系統分享選單,否則用 `<a download>` 存檔。

## 12. 新手導覽

- 導覽時整個畫面蓋一層透明的擋板(`position: fixed; inset: 0`)。
- **視覺上:** 亮框是一個 `box-shadow: 0 0 0 200vmax` 的元素,外面一圈都變暗,中間透明。
- **點擊判定:** 擋板收到點擊時,比對座標是否落在亮框的矩形內:
  - 在框內:前進。步驟有 `sheet` 的話,先真的打開那個面板,等它的 `close` 事件才繼續;有 `act` 的話,直接執行那顆按鈕原本的動作。
  - 在框外:亮框抖一下,不前進。
- **說明框位置:** 目標在畫面下半部時,說明框改放到上方,不會蓋住要點的東西。
- **無障礙:** 說明框裡有一顆視覺上隱藏的「下一步」,每一步都把焦點移到它身上,鍵盤和螢幕報讀的使用者按 Enter 也能前進。

## 13. 測試方式

用 Playwright 在 390 × 844 的手機尺寸上跑完整流程。目前這些腳本還不在 repo 裡,見 README 的待辦。

- **時間:** 用 `addInitScript` 包住 `Date.now`,加一個可以調的偏移量,就能瞬間「快轉」25 分鐘。
- **離開頁面:** 覆寫 `document.hidden` 再送出 `visibilitychange`,模擬切到別的 App。
- **通知:** 無頭瀏覽器沒辦法真的顯示通知,所以把 `ServiceWorkerRegistration.prototype.showNotification` 換掉,只記錄它被呼叫的時機和內容。
- **伺服器:** 用 `python3 -m http.server` 在 `http://localhost` 開,Service Worker 和通知 API 才會啟用。
